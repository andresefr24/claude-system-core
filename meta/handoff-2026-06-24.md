# Handoff — continúa el proyecto claude-system en Claude Code (2026-06-24)

Este archivo es un puente entre conversaciones. Lo escribió Claude en Cowork para que una sesión
fresca de Claude Code retome el hilo sin haber visto la conversación original. Bórralo cuando
sus hilos abiertos estén cerrados — el contenido durable vive en el resto del vault.

## Qué es este proyecto

Andrés está construyendo un **sistema de trabajo personal** para dejar de pelotear entre Cowork y
Claude Code, reducir retries y fricción, y delegar lo táctico mientras él se queda con lo
estratégico. Se materializó como **este plugin** (`claude-system-core`).

Principio rector: el plugin es **proceso** (cómo se trabaja), no contenido. El contenido de cada
proyecto vive en su propio **vault** (carpetas markdown: `mintstash-knowledge`, `tech-knowledge`).
Un cerebro de proceso, muchas memorias de proyecto.

## Cómo funciona el sistema (resumen)

Toda tarea recorre el mismo **backbone**:
intención → routing → retrieve → ejecución → verificación → reporte → Andrés decide → capture.

Las reglas siempre-activas viven en `plugins/core/rules/` y cada una tiene una skill cargadora en
`plugins/core/skills/`. Hay un segundo loop: la **retro** semanal que lee el friction-log, busca
enfermedades (causa raíz) no síntomas, y propone ≤3 mejoras. Para el detalle, lee `README.md` y
`meta/CHANGELOG.md`.

## CLAUDE.md listo para el repo de MintStash (copiar a su raíz)

```markdown
# CLAUDE.md — MintStash

Este repo opera bajo el sistema de trabajo personal (plugin claude-system-core).

## Vault de este proyecto
Contenido (decisiones, gotchas, normativos, estado): la carpeta mintstash-knowledge.
Si está fuera del repo, dale acceso con /add-dir.

## Reglas siempre activas
- Routing: al empezar una tarea, enruta por el tipo de output y declara la rama en una línea.
- Apertura (retrieve): roza siempre active-context, normativos, decisiones recientes y gotchas;
  profundidad según la rama. Si falta contexto que la tarea necesita, AVISA y PREGUNTA.
- Nunca de memoria: si existe un normativo (brand-identity, SCHEMA, CONVENTIONS), léelo antes de producir.
- Reporte: TL;DR → "Necesito que decidas" → cuerpo conceptual → "Confianza y huecos".
  Registro llano por defecto; los deep dives los pido yo.
- Cierre (capture): al terminar, propón los deltas durables para el vault y espera mi OK
  antes de escribir. Mejora del proceso → friction-log del repo claude-system; del proyecto → vault.

## Frontera de herramienta
Este repo es código: el trabajo serio (tests, migraciones, git, refactors) se hace aquí.
```
